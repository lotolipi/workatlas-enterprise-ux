# WorkAtlas — Product Definition v1

**Status:** Concept / Product definition
**Product type:** Hybrid Work Operating System
**Author:** Shilpi Mishra (Lotolipi)

## Product vision
From individual work to collective clarity.

WorkAtlas explores how personal productivity and shared team visibility can coexist in one coherent digital workspace.

## Problem statement
Individual contributors need clarity about their assigned work, priorities, deadlines, and blockers. Team leads need visibility into ownership, project progress, and work requiring attention.

Hypothesis: Connecting personal task management with shared work visibility may reduce coordination friction and improve clarity.

This hypothesis has not yet been validated through WorkAtlas user research.

## Proposed users
### Primary: Individual contributor
A designer, analyst, or knowledge worker managing tasks and updating work progress.

### Secondary: Team lead
A person coordinating projects, ownership, deadlines, and blockers.

These are provisional roles, not research-validated personas. Permissions are not yet defined.

## Primary workflow
1. Open My Day to review assigned work.
2. Select a task and review its context.
3. Update the task status.
4. See the corresponding change reflected in Team Work.
5. Review the activity history.

This is a proposed WorkAtlas workflow, not an implemented or tested journey.

## MVP scope
- My Day: personal task overview
- Work Board: shared task visibility
- Add Work: task creation
- Task details and status updates
- Basic project association
- Simplified activity history
- Responsive desktop and mobile interface

## Out of scope for v1
- Team availability management
- Recognition and sessions
- AI recommendations
- Advanced permissions
- External integrations
- Production multi-user synchronization

## Prototype evaluation goals
Evaluate whether users can:
1. Identify their next task.
2. Update its status.
3. Understand its relationship to shared team work.

No usability outcomes or performance improvements have been measured yet.

## Evidence and provenance
This independent project draws on the author's experience designing an internal enterprise work-management application.

Prior experience includes work boards, project tracking, team visibility, task creation, activity updates, and responsive layouts. The source application remains partially functional, and some permissions and editing behaviors are unverified.

WorkAtlas is a separate conceptual reconstruction using fictional scenarios and synthetic data. It does not reproduce employer-owned source code, internal screenshots, confidential records, or proprietary assets.
